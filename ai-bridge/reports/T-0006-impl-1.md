# T-0006 — implementation report 1

**Task:** almond: a terminal system-information command

## What changed and why

New command `almond` (`desktop/defaults/usr/bin/almond`; the build copies `desktop/defaults/usr/` to `/usr/`, so it lands in `/usr/bin/almond` without touching `scripts/build.sh`).

It prints a small ASCII almond in brown and gold next to:

- **Edition:** `PRETTY_NAME` from `/etc/os-release` (falls back to `/usr/lib/os-release`)
- **Kernel:** `uname -sr`
- **CPU:** model name and logical CPU count from `/proc/cpuinfo`
- **GPU:** names from `lspci -mm` (pciutils is already in the image); without lspci, the PCI vendor and device IDs from `/sys/class/drm/card*/device`, with a vendor name only for a short list of known IDs
- **RAM:** MemTotal − MemAvailable, the same "used" figure as `tests/measure-memory.sh`
- **Uptime:** from `/proc/uptime`

Anything unreadable shows "unknown". Options: `--no-logo`, `--no-color` (colours also turn off when output is not a terminal, or when `NO_COLOR` is set), `--help`. POSIX `sh`; no new packages; nothing stays running.

Tested on macOS with `dash` against fake trees: a VM-like system with a fake `lspci` (all fields filled), the `/sys` fallback (found "VirtualBox (PCI 80ee:…)"), and an empty system (every field "unknown", exit 0). Unknown options exit 2. Two bugs found and fixed during testing: uneven mark widths, and the `/sys` fallback skipping cards when the path contained a hyphen.

## Known limitations
